# User Story: working_prototype_instead_of_mockups

**ID:** US-15

## Story

As a product manager or designer,
I want the winning idea to come back as a running app I can click,
so that I can test it for real without paying for a full design-and-build cycle first.

## Acceptance criteria

- The output of a sprint is a deployed, interactive build — not a static mockup or wireframe.
- Turnaround is fast enough to treat as a prototyping loop (sprint cadence, not release cadence).
- The prototype is reachable by the community from the board itself (see [preview_the_shipped_feature](story__preview_the_shipped_feature.md)).
- Discarding a prototype is cheap: an unvalidated feature can roll back or decay without wasted design work.
